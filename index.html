Causal-EGraph

Python · causal discovery · equality saturation

Does keeping many candidate causal graphs at once, instead of greedily committing to one, find the right structure more often?

Most causal discovery methods (PC, GES, NOTEARS) climb toward a single best graph. This project keeps many statistically indistinguishable graphs in an e-graph, explores them with rewrite rules, and picks the best DAG at the end using BIC or a learned cost model. It's built from scratch: skeleton search, Meek's rules, BIC scoring, exact extraction by dynamic programming, and benchmarks against PC and GES.

Finding: across 4,788 synthetic trials, exhaustive search recovered the correct structure 92.7% of the time vs 67.9% for a greedy search using the same scores. On data from the real Sachs protein network, it matches PC and beats GES at the original experiment's sample size, and all three recover the exact structure at 20,000 samples.

RuleForge

Python · egglog · program synthesis · 2026

If you already know two programs are equivalent, how much of the rewrite rule connecting them can you recover automatically?

SkeleShare (CGO 2026) optimises programs built from skeletons like Mv and Conv using hand-written rewrite rules. RuleForge takes pairs of equivalent programs, anti-unifies them (Plotkin's least general generalisation, with lambdas handled up to renaming), reads off a rewrite rule, and checks it in egglog. 

Mv(?w0, ?w1, dotF)  →  PaddedMv(?w0, ?w1, dotF)
Finding: all seven rules tested from the paper's Figure 10 were recovered with the expected shape, and all load and fire in egglog. The write-up is upfront about the limits: the rules come out narrower than the paper's, and the check confirms the rules fire, not that they preserve meaning.

Nova compiler in progress

C++20 · CMake · compilers

How does a compiler actually work, from raw text going in to machine code coming out?

Nova is a small programming language, and this is its compiler, written from scratch in C++20 to learn every stage by building it. The front end works today: a lexer, a hand-written recursive descent parser with correct operator precedence, an AST walked through the visitor pattern, and semantic checks for undeclared and duplicate variables. 

let width  = 4;
let height = 10;
let area   = (width + height) * 2;
Next: control flow and functions, a type checker, then an IR with SSA form, classic optimisations (constant folding, dead code elimination, GVN) and LLVM code generation. The README keeps an up-to-date list of what's done and what's left.

DanfoSim

Python · PyTorch · agent-based simulation · transport

Does the flexibility of Lagos's informal danfo minibuses actually beat a fixed-route, fixed-schedule bus system on the same roads?

A multi-agent simulation of Lagos's informal transit: vehicles that leave when they're full enough, pick up passengers anywhere along the road, and sometimes cut a trip short to chase better demand. It runs against a fixed-route baseline with the same network, fleet and passengers, 200 simulated days at once as batched tensor operations. Every parameter is documented as either sourced or tuned.

Finding: informal transit wins overall, serving more than twice the trips with the same fleet. The exception is the evening peak, where the two are statistically indistinguishable.

RedQueen

Python · PyTorch · artificial life · evolution

When predators and prey evolve their own neural-network brains, is there a real arms race, or does it just look like one?

A 2D world where up to 2,000 prey and 200 predators each carry a tiny evolved neural network, with no reward function, just energy and reproduction. Instead of judging by eye, I fixed a testable definition of "arms race" before running anything, and measured each species against frozen opponents across 5 seeds of 100,000 steps.

Finding: no arms race. Predators improved significantly in every seed, while prey never did. This is one-sided predator escalation, not a Red Queen dynamic, and it held across sweeps of mutation rate, population size and sensing setup.

Matrix Multiply Autotuner

C · Python · performance tuning

How much faster can the same matrix multiply get just by searching over tile size and loop unrolling?

A tunable C matrix multiply, a timing harness that takes the median of repeated runs, a correctness check against NumPy, and two searches: brute force over all 24 settings, and random sampling of 8.

Finding: about 1.7× faster (22.0 ms → 12.7 ms) from changing two numbers. Unrolling mattered most; tile size barely mattered at this matrix size. Random search on a third of the settings landed within about 8% of the best.
